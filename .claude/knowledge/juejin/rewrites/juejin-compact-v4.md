# 你的Claude聊到一半开始"编"——我翻了459个会话的压缩记录，发现这不是你的幻觉

你有没有遇到过这种情况——

聊了两个小时，Claude 突然开始用 TypeScript。你明明一开始说了"纯 JavaScript，不要 TS"。你以为它忘了。翻聊天记录——那条消息已经被压成了摘要，你的原话早没了。

更隐蔽的情况：它没忘。它还遵守。但遵守的是被压缩稀释过的版本。"不要 TypeScript"→"偏好某些语言"→"编程偏好"——每次压缩吃掉一点信息，三轮之后意思全变了。

**这件事和 Prompt 写得好不好没关系。上下文被压缩了，压缩不会通知你。**

---

## 压缩是怎么吃掉你的规则的

AI 对话超出上下文窗口上限时，Claude Code 会把旧对话**压缩成摘要**，腾空间给新消息。

真正要命的是——它不是压缩一次。是**在上一次压缩的基础上再压缩。** 有损压缩叠有损压缩：

```
你写下的精确规则
    ↓ [第1次压缩] — 变成摘要："用户偏好JavaScript"
    ↓ [第5次压缩] — "偏好某些语言"
    ↓ [第13次压缩] — 只剩"编程偏好"两个词
    ↓ [第16+次压缩] — 你的原始规则彻底消失了
```

Claude 不知道这件事。它还在认真工作。但它用来理解"你让我干什么"的上下文，已经被多轮压缩替换成了一份模糊的、AI 自己写的摘要。

这就是为什么长 session 里 AI 会开始"编"——不是它故意的，是它的地图已经不准了。

---

## 我翻了 459 个会话的数据

意识到这个问题之后，我写了个脚本 `compact-counter.py`（MIT 开源），Hook 进 Claude Code 的压缩生命周期。每次压缩自动记录时间、触发方式、累计次数。

从 6 月 16 日至今，追踪了 **459 个会话**。

| 压缩次数区间 | 会话数 |
|------------|-------|
| 0 次 | 430 |
| 1-5 次 | 14 |
| 6-10 次 | 3 |
| 11-20 次 | 6 |
| 21-50 次 | 4 |
| 51 次以上 | 2 |

绝大多数 session 不会触发压缩。但长 session——那些真正干活的两小时以上的 session——**29 个中发生了 425 次压缩事件。** 单个 session 最高纪录 121 次。

---

## 我发现了一条曲线

观察这些长 session 的行为表现，我发现了一个规律——不是单调递减，是 U 型：

```
AI表现
  ↑
  │     ╱‾‾‾‾‾‾‾‾╲
  │    ╱            ╲
  │   ╱   最 佳 区    ╲
  │  ╱                ╲
  │ ╱                  ╲
  │╱                    ╲
  └──────────────────────────→ 压缩次数
     0-2    3-8    9-15   16+
     预热   甜蜜区   衰减   高风险
```

**0-2 次**：还不了解你的项目，犯错多。

**3-8 次**：理解你了，但早期规则还没被压掉。**最佳状态。**

**9-15 次**：早期约束开始被稀释。微妙的错误开始出现。

**16 次以上**：你的原始指令几乎被多轮摘要替代。AI 在残缺地图上工作——它自己不知道。

这个曲线的直觉来自 50+ 个长 session 的行为记录。但说实话——**这是观察，不是测量。** 混淆变量没排除——长 session 人也累了、任务本身更难了。

我需要主动测试，而不是被动观察。

---

## 我设计了一个实验（然后第一轮什么也没测到）

核心思路：同一批指令，在不同退化级别下测试 AI 的遵守率。

第一轮，5 条标准指令——"注释用中文"、"变量用 snake_case"、"代码后写测试"。

5 个退化级别 × 2 次重复 = 50 次 API 调用。SHA256 预注册。

**结果：50 个 trial 全部满分。**

懵了。检查了三遍评分脚本。没错。

问题在于——**这些指令跟模型的默认行为一模一样。** Python 天然用 snake_case，中文任务天然出中文注释。退化到只剩"写代码"两个字，模型还是合规的——因为它本来就这么干。

第一轮没测到衰减。但它告诉我一件更重要的事：**跟模型默认行为一致的规则，几乎不会被压缩吃掉。** 反过来说，真正危险的是那些要求模型**违背默认行为**的规则。

---

## 第二轮：换了逆向指令，断崖出现了

这次我换了 5 条**故意违反模型默认行为**的指令：

| 逆向指令 | 对抗什么 |
|---------|---------|
| Python 代码块用 ` ```js ` | 模型天然写 ` ```python ` |
| 变量用 camelCase | Python 惯例是 snake_case |
| 注释用英文（中文提问） | 模型匹配提问语言 |
| 只输出代码，禁止解释 | 模型天然想解释 |
| 以 VERIFICATION_COMPLETE 收尾 | 不在模型习惯里 |

同样的 50 次调用。这次有信号了：

```
Level    说明              遵守率   满分率
L0       完整指令          100%     100%
L3       简化到一句话        80%      60%
L8       简化到几个词       100%      80%
L12      简化到两个词        60%      20%    ← 断崖
L18      几乎退化消失        60%      20%
```

**不是光滑曲线。是阶梯。** L8 到 L12 之间——指令从"几个词"退化到"两个词"——满分率从 80% 断崖到 20%。

逐指令看：

- **格式约束最抗退化**：` ```js ` 退化到"注意格式"还能部分遵守，从没跌回 Python 默认
- **语义约束断崖跌落**：英文注释退化到"写清楚注释"→ 模型立刻回归中文
- **有些指令天生免疫**：camelCase 在所有级别满分——指令的语义信号太强，退化不掉

这跟我的经验曲线不完全吻合。U 型暗示中等压缩（L3-L8）应该有最好的表现——但在逆向指令下，L3 反而出现了首次下跌。

## 搜了一下论文，发现不是只有我注意到了

带着结果翻了翻论文，发现学术界也在测同一件事。

**2025 年 12 月的一篇论文**（[CDCT Benchmark](https://arxiv.org/abs/2512.17920)，9 个模型，5 个压缩级别）的核心结论：**指令遵守率确实呈 U 型曲线——中等压缩时的遵守率低于极端压缩。** 根因是 RLHF 的 helpfulness 训练：模型半懂不懂的时候，会"帮忙编一个"——然后编错。

另外三篇从不同角度解释了这件事：[Lost in the Middle](https://arxiv.org/abs/2307.03172) 证明 LLM 对上下文中间的信息利用率最低（压缩把早期指令从"开头"推到"中间"）。[Gist Token 压缩研究](https://aclanthology.org/2025.acl-long.241/) 把失败模式分成三类：边界丢失、意外丢失、渐进衰减。还有一篇[量化模型"懒惰"](https://arxiv.org/abs/2512.20662) 记录了和我 R2 一模一样的行为——"词在，但位置错了"。

也就是说，**我观察到的现象，学术界用更严谨的方法独立验证了。** 这不是我一个人在瞎猜。

---

## 诚实地说

论文的统计方法比我严谨太多了。9 个模型、跨模型比较、盲评、统计检验。

我的 pilot——n=2、人工退化、纯 regex 评分、单模型——够发现现象，不够当证据。

但论文有一个关键盲区：**它们没在真实 Claude Code session 里跑过。** 论文是实验室里压缩 prompt 然后测。我的 compact-counter 是在真实工作流中盯着真实压缩事件——425 次，459 个 session。论文验证了 U 型曲线；我的数据记录了 U 型曲线在工程环境里的实际代价。

还有论文没有覆盖的：**压缩恶性循环。**

```
压缩 → 前缀改变 → cache miss → token 成本翻倍 → 消耗加速 → 更多压缩
```

这是工程痛点，不是学术问题。用 Claude Code 超两小时的人都会撞到——cache miss 后 API 费用肉眼可见地涨，然后又触发更多压缩。

## 如果你也用 Claude Code 做长 session

**1. 压缩超过 20 次，开 `/reset`。**

不是坚持的问题。上下文已经在摘要之上压摘要，压了 20 轮。原始指令早就没了。我的 compact-counter 会 Hook 进去自动提醒。

**2. 规则顺着模型写，别逆着。**

我的 R1 说明：跟模型默认行为一致的规则，退化到只剩骨架模型也会遵守。

举个例子：你想让 Python 代码用 snake_case——**根本不用写这条规则。** Python 生态天然 snake_case，模型怎么写都是对的。但你想让 Python 代码用 camelCase——这条规则每次压缩都会丢一点，10 次压缩之后基本等于没写。

所以写 CLAUDE.md 的时候想清楚：**哪些规则是"限制模型不做它本来就不做的事"（白写），哪些是"限制模型做它天然会做的事"（会被压缩吃掉）。** 尽量把后者转成前者。

**3. 格式约束比语义约束更抗压缩。**

表面规则（用什么标记、输出格式）比深层语义规则（用什么语言、遵守什么风格）更不容易被压缩破坏。如果需要长期遵守：把规则写成格式要求。

**4. 不要信任 AI 写的压缩摘要。**

尤其是 10 次压缩之后的摘要。它在退化上下文里生成的退化摘要，语气可能很确定——但其实是一份二手地图。翻回原始输出看，比看摘要安全。
