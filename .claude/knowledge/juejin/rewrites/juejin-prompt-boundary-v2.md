# 别瞎调 Prompt 了——跑完 100 次实验，我搞懂了模型的能力边界在哪

上个月我跑了一个实验：5 条指令，5 个退化级别，2 次重复。SHA256 预注册。机械正则评分。

**第一轮。50 次 API 调用。全部满分。**

我懵了。检查了三遍评分脚本。不是 bug。

不是实验设计有问题。是指令选错了——"注释用中文"、"变量用 snake_case"、"函数加 docstring"。这些规则跟模型的默认行为一模一样。退化到只剩"写代码"三个字，模型还是合规的。因为它本来就这么干。

今年 3 月我在掘金发过一篇同题文章，那时候的结论是 Prompt 改不了模型的能力天花板。证据只有三天踩坑和一个 QLoRA。现在有一百次调用和四篇论文背书——结论没变，但证据变了。

---

## 不是实验失败了——是指令选错了

我第一轮用的什么指令？

"注释用中文"、"变量用 snake_case"、"代码后建议测试"、"函数加 docstring"、"类型提示用 typing 模块"。

问题在哪？这些指令跟模型的默认行为**一模一样**。Python 天然用 snake_case，中文任务天然出中文注释，Python 好习惯天然写 docstring。退化到"写代码"三个字——退化级别 L18——模型还是合规的。因为它本来就这么干。

**这条 null result 教会我一件事：跟模型默认行为一致的规则，几乎不受压缩影响——因为你根本没在约束它，你只是在描述它的习惯。**

反过来说，真正危险的规则，是那些要求模型**违背默认行为**的规则。

也就是——大部分真正有用的规则。

---

## 第二轮：换逆向指令，断崖就出来了

我换了 5 条**故意违反模型默认行为**的指令：

| 规则 | 对抗什么 |
|------|---------|
| Python 代码块用 ` ```js ` 不要用 ` ```python ` | 模型天然写 ` ```python ` |
| 变量用 camelCase | Python 惯例是 snake_case |
| 注释用英文（中文提问） | 模型匹配提问语言 |
| 只输出代码，禁止解释 | 模型天然想解释 |
| 结尾输出 `VERIFICATION_COMPLETE` | 不在模型习惯里 |

每条指令写了 5 个退化版本——模拟长 session 中被反复压缩后还能剩下什么：

```
L0:  "所有注释必须用英文写。不要用中文写注释。即使用户用中文提问，注释也用英文。"
L3:  "注释用英文写，不用中文。"
L8:  "注释用英文。"
L12: "写清楚注释。"
L18: "写代码。"
```

同一批退化链，50 次调用。**这次——信号非常清楚。**

```
退化级别     合规率      完全合规率
L0          100%       100%
L3           80%        60%
L8          100%        80%      ← 居然回升了
L12          60%        20%      ← 断崖
L18          60%        20%
```

退化不是平滑曲线。从 L8 到 L12 有一个**断崖**——完全合规率从 80% 暴跌到 20%。

更有意思的是逐条指令的差异：

| 指令 | L0 | L3 | L8 | L12 | L18 | 发现了什么 |
|------|----|----|----|----|----|-----------|
| ` ```js ` 替代 ` ```python ` | ✅ | ⚠️ | ⚠️ | ⚠️ | ⚠️ | 退化到部分合规，但从未回退到默认 |
| camelCase 变量 | ✅ | ✅ | ✅ | ✅ | ✅ | **高度弹性**——概念太强，但 L12+ 开始混杂 snake_case |
| 英文注释（中文任务） | ✅ | ✅ | ✅ | **❌** | **❌** | **这是断崖本尊**——L12 "写清楚注释" → 中文回来了 |
| 纯代码无解释 | ✅ | **❌** | ✅ | **❌** | **❌** | 振荡——模型在服从和解释之间反复横跳 |
| VERIFICATION_COMPLETE 收尾 | ✅ | ✅ | ✅ | ⚠️ | ⚠️ | 关键词存活了，但位置开始漂移 |

三条规律：

**格式约束比语义约束更抗压缩。** ` ```js ` 这条退化到 L18 还是部分合规——从来没用回 ` ```python `。但"写英文注释"这条，退化到"写清楚注释"的瞬间就崩回了中文。表面规则（用什么标记）比深层规则（用什么语言）更能扛住压缩。

**最难守的不是复杂规则——是"禁止做默认的事"。** "不要解释"这条，L3 就崩了一次，L8 又恢复了，L12 再崩。"只要代码"退化成了"简洁输出"——模型的理解是"简洁输出=写代码+简要说明"。但你要求的不是"简要"，是**没有**。你要求模型压制它的解释本能——几句话的退化文本根本传达不了"禁止"这个语义。

**L8 的回升可能是真实的，不是噪音。** L3（~一句话）有时太模糊，模型不确定该做什么。L8（几个关键词）反而更清晰——"用驼峰命名"、"注释用英文"。信息量少了，但信噪比可能**高了**。到 L12（"注意命名"、"写清楚注释"），语义崩了——模型知道该注意什么但不知道注意什么方向，于是回到默认行为。

## 为什么偏偏是 L12？论文说是 RLHF helpfulness 的锅

后来我翻到一篇 2025 年 12 月的预印本——**CDCT Benchmark**。他们在 9 个主流大模型上做了几乎一模一样的事。

核心发现：**指令遵守率不是单调下降的——中等压缩时反而最差。** 根源是 RLHF 的 helpfulness 训练。当模型部分理解了一条退化指令，helpfulness 机制触发——"这条指令不完整，让我猜一下用户想要什么"——然后猜回了默认行为。**去掉 helpfulness 信号后，约束遵守率提升了 598%。**

这就解释了我的 L8→L12 断崖。L8 时"注释用英文"还有足够语义。到 L12，"写清楚注释"——模型看到了"注释"，helpfulness 说"用户想要好注释"，而模型的"好注释"= "跟任务语言匹配" = 中文注释。**退化的不是指令的清晰度——是指令被 helpfulness 覆盖了。**

另外三篇论文给了机制层面的补充：
- **Lost in the Middle**（TACL 2024）：LLM 对上下文开头和结尾利用最好，中间最差。长 session 中早期指令被压缩后不断从"开头"推到"中间"——模型越来越难注意到
- **Gist Token 失败模式**（ACL 2025）：三种压缩失败——边界丢失、意外丢失、沿途丢失。我的 compact-counter 数据对应第三种
- **Quantifying Laziness**（2025）："部分合规"——遵循退化指令的字面但偏离精神。我的 `VERIFICATION_COMPLETE` 就是：关键词活了，位置约束死了

## 实地数据：459 个 session 说了一样的故事

实验室退化是模拟的——手动写的退化链。真实压缩是 LLM 自己生成摘要。一样吗？

我用 compact-counter 追踪了 459 个 Claude Code session：

```
每个 session 的压缩次数     session 数
0                          430        ← 大多数永远不会触发压缩
1–5                         14
6–10                         3
11–20                        6
21–50                        4
51+                          2         ← 29 个 session 产生了 425 次压缩事件
```

单 session 最高：**121 次压缩**，横跨将近三天。

这 425 次压缩全是真实的 LLM 摘要。行为模式跟实验室一致——长 session 后期，早期指令"消失"了。模型开始写 TypeScript（明明说过只用 JS），开始写中文注释（明明要求英文）。格式规则（输出结构、文件命名）坚持得更久；深层规则（代码风格、语言选择）先崩。

实验室说 L8→L12 有断崖。实地数据加了一层：你不是在做实验，你**根本不知道**自己的规则退化到了 L12。因为压缩摘要是模型自己写的——它不会说"我忘了你的指令"，它会自信地给你一个摘要："用户偏好 JavaScript"——但这个摘要是从"纯 JavaScript，禁止 TypeScript，禁止 any 类型"经过三轮退化来的。

**摘要的退化你不知道。模型也不知道。两个都不知道的情况下，错了不知道错在哪。**

## 外加一个教科书般的正反馈循环

学术论文覆盖不到这块——因为这是工程现象，不是模型属性：

```
压缩 → 上下文前缀改变
    → Prompt cache 命中率归零
    → 每次调用 token 翻倍
    → session 消耗加速
    → 更快触发下一次压缩
    → cache 命中率继续下降
```

**正反馈。** 压缩不仅降低指令遵守率——还**加速自己的频率。** 每次压缩让下一次更可能发生，因为 cache 被破坏了。长 session 里你感觉费用涨了——但它不会说为什么。（我把 `autoCompactWindow` 调到 400K tokens，配合 DeepSeek V4 Pro 的 1M 窗口——给足了缓冲。大多数人不知道这个参数。）

## 所以，怎么用？

3 月份我给的框架是"调 Prompt 前先问三个问题"——有了数据之后，升级成五层：

**① 这个约束能用正则/时间戳/退出码检查吗？**
→ 机械门。不经过 LLM。最可靠。模型说服不了 `exit code != 0`。

**② 是格式层面的约束吗？**
→ Prompt + 格式强制标签。高性价比。格式比语义更抗压缩。

**③ 涉及知识和推理吗？**
→ RAG + 微调。Prompt 改注意力方向，不改概率分布。

**④ 逆着模型默认行为吗？**
→ 降低期望，或者换个实现方式。逆默认的指令在 L12 处崩溃。

**⑤ 长 session 中会衰减吗？**
→ 追踪压缩计数。≥20 次就 `/reset`。20 轮后的摘要不是你写的规则了。

**Prompt 是第一层，不是唯一层。** 大部分人在第一层卡住——然后发现换了个模型规则就失效（概率分布变了）；或者长 session 中模型"忘了"规则（压缩吃掉了）。

这些都不是"Prompt 写得不够好"能解决的。**每类问题对应架构中的一层——那层可能根本不是自然语言。**

---

## 说真的——这个实验的局限

n=2 per condition，不够做显著性检验。L3 的下降和 L8 的回升可能是噪音。退化链是手动写的，不是真实压缩产物。单模型（DeepSeek V4 Pro）。评分是机械正则，A4 的振荡可能部分是 scoring artifact。

完整实验需要每个模型 ~600 次调用 + 15-20 小时分析。大四找工作期间先挂着——方向是明确的。

---

三个月前我说"Prompt 有天花板"。那时候的证据是三天踩坑。现在的证据是一百次 API 调用、二十九个重度 session 的压缩数据、四篇论文的交叉验证。

结论没变。重量变了。

**Prompt 的天花板是模型概率分布的天花板。** 天花板以下——格式、语气、推理步骤——Prompt 能做很多。天花板以上——知识、推理深度、自我验证——Prompt 碰不到。不是替代 Prompt。是当 Prompt 不够用的时候，知道下一个工具在哪。
